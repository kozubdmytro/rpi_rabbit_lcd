## Проект и разрешения

- LCD-папка: `D:/desktop/raspberry pi/lcd version rpi rabbit`.
- Git: https://github.com/kozubdmytro/rpi_rabbit_lcd.git, ветка main.
- Основа — рабочая матричная версия с её незакоммиченным cleanup.

## UI и управление

- Прежний UI `src/hub_demo.h`, шрифты, меню, анимации, жесты сохранены.
- 64x64 увеличивается строго в 5x5 блоки; область 320x320 на LCD 480x320
  занимает x=80..399, y=0..319. Нет растяжения или сглаживания.
- По сторонам только две серые сенсорные линии толщиной 9 пикселей:
  x=6..14 и x=465..473, y=12..307. Hit areas занимают боковые поля x=0..79 и x=400..479.
- `src/lcd_strip.h`: геометрия и обычный непрерывный захват слайдера.
  Контакт начинается в любом боковом поле и сохраняется до отпускания:
  горизонтальный уход или пересечение экрана больше не отменяет его.
  Контакты, начатые на центральном UI, игнорируются. Положение сверху вниз,
  без 12 зон; median из трёх отсчётов отсекает одиночные выбросы Y.
- После жалобы пользователя на обрывы удалена ошибочная отмена при выходе
  из узкой зоны. В LCD HubDemo убраны MPR121 endpoint padding 0.04/0.92:
  нормализованная координата слайдера напрямую задаёт полный диапазон.
  Отрисовка и исходный матричный проект не менялись.
- `src/lcd_touch.h`: nonblocking evdev ADS7846, автообнаружение по имени,
  SYN_REPORT, безопасная отмена при SYN_DROPPED/отключении, reconnect 1 s.
- `/home/srlab/rpi_rabbit_lcd/touch-calibration.conf` — прежняя калибровка
  этой же панели, SR_TOUCH_V1. Скопирована из старой папки без изменения
  оригинала, исключена из Git. Смена FBTFT rotate=90 на DRM rotate=180
  сохраняет прежнюю ориентацию и эту калибровку.
- Полоски остаются на физических краях при повороте UI. Brightness 0..100
  масштабирует RGB и линии, ввод работает при 0%. Подсветка не выключается.

## Ускоренный вывод

- Восстановлен проверенный backend из коммита матричного репозитория
  `f5b172e`, адаптирован под нынешний API и обе полоски.
- `src/drm_renderer.cpp`: native ILI9486 DRM, RGB565, блокирующий DIRTYFB
  изменённого прямоугольника. Полный upload при старте и раз в две секунды.
  Статичные полоски не расширяют обычные UI-обновления до всего экрана.
- `src/lcd_renderer.cpp` автоматически выбирает DRM при ili9486drmfb;
  прежний FBTFT backend остаётся для старого профиля.
- Native backend захватывает graphics console и штатный CPU performance
  governor, восстанавливает их при выходе. `restore-performance.sh` и
  `deploy/recover-console.py` дают systemd cleanup после прерывания процесса.
- Make и CMake включают libdrm через pkg-config, если пакет доступен.
  На Pi libdrm 2.4.134 уже был установлен; пакеты не устанавливались.

## Проверено для DRM

- Make-сборка и существующий C++ тест framebuffer/rotation/двух полосок/
  Quick/hold/brightness save прошли на Pi.
- Аппаратный замер: 120 завершённых полных обновлений UI за 6.77085 s,
  **17.723 FPS** на SPI 32 MHz, с двумя полосками и периодическим полным
  refresh. Это скорость завершённых загрузок, не оптический scan rate.
- Проверен активный DRM scanout попиксельно: RGB565, точные блоки 5x5,
  обе линии, чёрные поля; no-op, partial update, brightness 0/50/100.
- SPI errors=0, timedout=0. CPU policy и graphics console восстановились
  после теста. Результат: `/home/srlab/rpi_rabbit_lcd/build/lcd-performance.txt`.
- После установки active, NRestarts=0, SHA процесса совпал, API HTTP 200,
  ready=true, одна сохранённая нода, gateway journal не изменён.
  Логи подтверждают native DRM и открытие ADS7846.
- CMake и reboot не запускались. Визуальную плавность и физические жесты
  оценивает пользователь; искусственная проба не заменяет его оценку.
